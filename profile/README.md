forked.win is a small group of people who contribute to open-source projects that aren't ours.

Most of the software the rest of us rely on is looked after by one or two people in their spare time. Issues pile up, the documentation drifts out of date, and pull requests wait weeks for a review. We take some of that work off their hands. We pick an issue, fix it, and send the patch to the maintainers the same way any other contributor would.

Nothing stays in our forks. If a change never makes it upstream, we don't count it as finished.

## What we work on

Mostly bugs that have been open for a long time, documentation that no longer matches the code, slow startup and build times, accessibility problems, and missing tests. We stay away from big rewrites and new features unless a maintainer has asked for them.

## How it works

Before we touch anything, we read the project's contributing guide and check that the maintainers actually want the change. Then we fork the repo, make the fix on a branch, and have a second member read it over. After that we open the pull request and deal with whatever feedback comes back. If the maintainers decide not to take it, we say thanks and move on.

## Working with maintainers

We follow each project's rules, even when we'd have done it differently. We keep pull requests small and ask before starting anything large. Our own work is public, so you can read every patch and every review.

## Join us

If there's a bug in some project that keeps annoying you, that's a good place to start. You don't need to be experienced. Look through our repositories, or [start a discussion](https://github.com/orgs/Forked-Win/discussions) about a project that could use help. There's more about us at [forked.win](https://forked.win).

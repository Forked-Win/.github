## 🍴 Who we are

forked.win is an open-source group that contributes to other people's projects.

Plenty of good software stalls because the maintainers are stretched thin. Bugs sit open for months, the docs fall behind, and nobody has time to review a big pile of requests. We step in. We pick up the work that's been waiting, do it carefully, and hand it back as a pull request that's ready to merge.

Everything we make goes upstream. If a fix only lives in our fork, we haven't finished.

<br>

## 🔧 What we work on

| | |
| :-- | :-- |
| **Bug fixes** | Crashes, edge cases and the issues that have been open for ages. |
| **Documentation** | Install guides, examples and READMEs that match the code as it is today. |
| **Performance** | Slow startups, wasteful loops and heavy dependencies. |
| **Accessibility** | Keyboard support, screen reader labels and readable contrast. |
| **Tests and tooling** | Missing tests, flaky builds and clearer error messages. |

<br>

## 🌿 How a contribution happens

**1. Fork.** We find an open issue, read the project's contributing guide, and work in our own copy.

**2. Fix.** We keep changes small and focused, with tests and clear commit messages. A second person reviews before anything leaves the group.

**3. Send it back.** We open the pull request, answer feedback, and stay on it until it lands or the maintainers say no thanks.

<br>

## 🤝 How we behave

- **Maintainers come first.** We ask before starting anything large, and we follow each project's rules.
- **Small pull requests.** We never send something that creates more review work than it saves.
- **We stay with it.** We respond to feedback and finish what we start.
- **Everything is public.** Our patches, our reviews and our mistakes are all in the open.
